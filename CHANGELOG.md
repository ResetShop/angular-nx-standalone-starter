# Changelog

All notable changes to this starter are documented here. Forks should read this file before every upstream merge — it is the single source of truth for what changed upstream and whether any of those changes affect fork-owned code or require migration work.

Each version has one section, written once when that version is released. It opens with a summary of what changed and why, lists under **Fork migration** what a fork must do (present only when a fork has to act), links to every merged pull request, and ends with one line per issue grouped by theme. Pull requests do not edit this file: the release notes are written at release time from the merged pull requests.

Versions follow the milestone plan. A version ships when its milestone is complete, and its number reflects the planned scope rather than strict semantic versioning, so a patch release can still ask something of a fork. When merging upstream, read the **Fork migration** section of every version between your last merge and the new one, whatever the version numbers say. Every version uses this layout; a version with nothing for a fork to do has no **Fork migration** section. Before 1.0.0, versions followed a `1.0.0-beta.N` naming convention while the fork-distribution model was being stabilized; the four pre-releases share one section at the end of the file.

## [1.1.0] — 2026-09-27

Version 1.1.0 moves the starter to Angular 22, Nx 23 and TypeScript 6 with strict mode on, and lets every signed-in user manage their own account. It is the largest release since 1.0.0, and it asks something of every fork: read **Fork migration** below before merging.

The first area is the **toolchain**. Angular 22.0, Nx 23.1 and TypeScript 6.0 land together, because each one requires the others ([#534]). Components now rely on Angular 22's default OnPush change detection, and a lint rule keeps it that way ([#551]). `@ngrx/signals` moves from a pinned pre-release to the stable 22.0.0 ([#553]). TypeScript's strict mode is now on across the workspace ([#560]). Turning it on also exposed a real bug: three API routes documented a generic "Forbidden" error instead of their actual reason for refusing ([#555]). Node.js moves to the 24.20.0 LTS release, and a new `docs/node-support-policy.md` explains why the starter follows the LTS line instead of adopting Node 26 ([#535], [#536]). Prettier is pinned to one exact version, so formatting no longer depends on the day you installed ([#559]).

The second is **account self-service**. Any signed-in user can open `/account` and change their own name. A before → after summary is shown before anything is saved, and the new endpoint can only ever edit the caller's own account ([#454]). Changing the email address stays admin-only until the new address can be verified; that is planned for 1.2.0 ([#588]). The sidebar footer now shows the signed-in user, with a menu for Account, Settings and Log out ([#586]), and the desktop sidebar no longer collapses ([#604]). `GET /api/auth/me` now reads the account from the database instead of from the session token. A rename therefore appears on the next page load, and a disabled user is signed out on their next navigation instead of up to 15 minutes later ([#454]).

The third is **user administration**. Admins edit a user's profile, roles and status in one drawer, check the changes as a before → after list, and save them in a single transaction. A failed role change can no longer leave an edit half-applied ([#453]). The user and role drawers no longer accept an invalid form ([#589]). Permission descriptions now follow the selected language ([#572]), and the row actions menu is built on the new shared `Menu` component ([#601]).

The fourth is **testing and CI**. Until now the integration suite could not fail: a failing run still exited successfully. It now fails properly, so a fork may see failures that were already there ([#585]). The code generators work again; they had broken under ES modules ([#590]). The shared Playwright fixture no longer hangs at teardown ([#557]), and the upstream guard checks run again when a stacked pull request is retargeted ([#583]). On the release side, an unused `nx release` configuration is removed and a protection rule for version tags is specified ([#486]).

Documentation gains a single reference for Angular dependency injection ([#482]) and setup instructions for the Zed editor ([#575]).

## [1.0.2] — 2026-07-24

Version 1.0.2 gives private forks a one-command way to take upstream updates, moves the starter to a `develop`/`main` branch model with an automated release pipeline, and makes Node.js 24 the only supported runtime. It also removes Nx Cloud, adds and tightens several repository-wide guards, and records the Railway deployment in the repository. Several of these changes ask something of every fork: read **Fork migration** below before merging.

The first area is the **fork and release workflow**. A client project that must stay private cannot be a GitHub fork of a public repository, so it lives as a private mirror. Run inside a mirror, `npm run upstream:pull` fetches upstream, prints the CHANGELOG changes since the last merge, merges `upstream/main`, resolves lockfile-only conflicts and finishes with `npm run ci:verify`; the separate `fork-init` tool creates the mirror in the first place ([#540]). Upstream now develops on `develop` and reaches `main` only through an automated release pull request, so every advance of `main` is a tagged release with its own CHANGELOG section. A new `/release-workflow` skill prepares each release by promoting the `## [Unreleased]` section to the new version and bumping `package.json`, and two workflows open the release pull request and publish the tag and GitHub Release ([#539]). Structured issue forms and a refreshed pull request template make new issues easier to triage ([#504]).

The second is **toolchain and CI**. Node.js 24 LTS is now the only supported runtime: `engines.node` is `^24.18.0`, and a new `.nvmrc` pins 24.18.0 ([#537]). Nx Cloud is removed and tasks use the local Nx cache only, so a stray access token can no longer fail CI or report a private mirror's runs to the starter's public Nx Cloud workspace ([#542]). The repository-wide guards now run as one Nx `check` target, both locally and in a new remote CI job, so a push that skipped the pre-commit hook no longer skips them ([#527]). One of those guards is new: code comments must explain the code as it is now, and an issue or pull request number in a comment fails the build ([#499]). The lint rule against direct `process.env` access now allows eight named files instead of three whole directories, and the integration tests read their settings through the typed environment schemas ([#501]).

The third is **styling**. Components whose host styling is a fixed set of utilities now declare it with `host: { class }` instead of `:host { @apply … }` ([#489]). Component stylesheets no longer carry the `@reference "#tailwind-theme"` line: a PostCSS plugin adds it at build time to every stylesheet that uses `@apply`, and the `ui-component` generator stops writing it ([#523]). The dashboard header and the health page now use the theme's semantic tokens instead of hardcoded grays, so both render correctly in dark mode ([#520], [#513]).

The fourth is **deployment**. A root `railway.json` records the Railway build command, start command and health check in the repository, so a deploy that cannot reach its database no longer replaces a healthy one ([#514]). Storybook can be served from a second Railway service by a small static server that uses only Node built-ins ([#547]). Vercel-specific wording and a dead Speed Insights stub are removed from the code and documentation ([#545]). A deploy that restarted in a loop on its startup database check turned out to have a connection configuration problem in the deploy environment; correcting that configuration resolved it, with no code change ([#511]).

### Fork migration

Every fork:

- [#537] - Use Node.js 24.18.0 or later (`nvm use` reads the new `.nvmrc`), move the Node version pins in your own CI workflows and deployment platform to 24.18, then run `npm install` to pick up `@types/node` `^24.13.3`. `engines.node` is now `^24.18.0`: an older runtime gets an `engines` warning from npm, and fails the install if your `.npmrc` sets `engine-strict=true`.
- [#542] - Delete the `NX_CLOUD_ACCESS_TOKEN` secret from your repository's Actions secrets and unset the token in your shells: `nx.json` no longer has upstream's `nxCloudId`, and `.github/workflows/ci.yml` sets `NX_NO_CLOUD: 'true'` and uses the local Nx cache only. If your fork uses its own Nx Cloud workspace, keep your own `nxCloudId` when you resolve the `nx.json` merge and remove `NX_NO_CLOUD` from your `ci.yml`.

## [1.0.1] — 2026-06-19

Version 1.0.1 prepares the starter for going public: it adopts the Apache-2.0 license, adds community-health files, removes hard-coded credentials, and cleans up the environment configuration and the integration-test teardown ([#488]). Several of these changes ask something of every fork, so read **Fork migration** below before merging. The `v1.0.1` tag and GitHub Release were published before the `package.json` version bump and this section; the section was written afterwards.

The first area is **public readiness**. The starter is now licensed under Apache-2.0, with `LICENSE.md`, `NOTICE.md` and a `license` field in every `package.json` ([#490]). `CONTRIBUTING.md`, `SECURITY.md` and `CODE_OF_CONDUCT.md` state the contribution policy: issues are welcome from anyone, pull requests come from ResetShop members, and vulnerabilities are reported privately. A workflow that runs only on the upstream repository closes pull requests from outside the organization ([#493]). A `CODEOWNERS` file routes reviews to the maintainers ([#488]). A personal email and a stray log file are removed from the tree, and the root `package.json` gains project metadata ([#494]). The README's setup guide is corrected and now points to files and symbols instead of line numbers, so it no longer goes stale with each edit ([#492]).

The second is **credentials and setup**. The database seed no longer creates an administrator from a password hash committed to the repository. It reads `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD`, prompts for them in a terminal, or stops with a clear error. `npm install` no longer runs migrations and the seed, so an install no longer fails on a machine without a database ([#491]). CI reads the integration-test admin password from a masked Secret instead of a Variable that public workflow logs could show ([#508]).

The third is **backend configuration**. The authentication environment schema is split into token, password and security schemas, and `CRON_SECRET` moves to the cron schema. A process that needs only the password cost or the lockout settings no longer exits when the PASETO keys are unset, and the variable names do not change ([#497]). The seed and permission-sync scripts use the same database connector as the API, so a dropped idle connection no longer crashes them ([#502]).

The fourth is **integration testing**. The suite now closes its database pool, always stops the embedded Postgres and removes its temporary directories, so it no longer leaves orphaned `node` processes holding memory, and CI's peak memory is bounded ([#517]).

## [1.0.0] — 2026-06-04

Version 1.0.0 is the first release of the starter under the fork-distribution model, and it consolidates everything merged since 1.0.0-beta.3. It replaces `.env` files with a validated environment contract, completes the password flows, adds a user detail page, a public landing page and end-to-end coverage of the reference app, and makes the dashboard usable on phones. Many of these changes ask something of every fork: read **Fork migration** below before merging.

The first area is **environment configuration**. Every backend variable is now declared in one of six Zod-validated schemas under `src/api/config/` and read through a `<domain>Env` object such as `dbEnv.PG_CONNECTION_STRING`; a missing or invalid value stops the process at start-up with a clear message ([#354]). The work landed in steps: configuration is injected where tests need other values ([#440]), every production read moves to the new objects ([#441]), the database scripts and `drizzle-kit` read them too ([#442]), and the old validation code is removed ([#443]). A lint rule now rejects any other `process.env` read ([#444]), and a guard fails the commit hook and `npm run ci` when a `.env*` file is in the tree ([#354]). `@resetshop/hono-core` no longer carries app-specific configuration ([#258]). The token-cleanup interval is now a duration string such as `24h`, like the other time settings ([#259]), and the production build no longer fails because a rate limiter read the configuration too early ([#450]).

The second is **authentication**. Users flagged to change their password are sent to a change-password page before they reach the dashboard ([#388]). A user who forgot their password can request a single-use reset link by email ([#428]). The request answers the same way, and just as fast, whether or not the account exists ([#433]), and its confirmation no longer lingers when the user comes back to the page ([#434]). The login and reset pages show a countdown while an account is locked or requests are rate-limited ([#436]). The login response now carries the user's roles and permissions, so permission-gated navigation is right from the first page ([#322]). Behind these, `AuthService` is split into focused services ([#420]) and password hashing sits behind one module ([#385]). Generating a temporary password no longer fails in development ([#371]) or makes a test fail at random ([#429]).

The third is **user and role administration**. Admins can reset a user's password; the new temporary password is emailed, never returned or logged ([#214]). Editing a user moves from a drawer to a detail page at `/dashboard/users/:id`, which stops admins from removing their own admin role ([#212]). The user API moves to plural paths, `/api/users*`, like its siblings ([#455]). Creating a user writes the identity, the password and the roles in one transaction, so a failure leaves nothing half-created ([#387]). Row actions move into a ⋮ menu ([#401]), and actions an admin cannot take on their own account are hidden ([#389]). The Spanish copy of the welcome email and the interface is corrected ([#251]).

The fourth is **navigation and feedback**. The root path `/` now serves a public, server-rendered landing page instead of redirecting to the login page ([#19]), and its unreachable "Go to dashboard" link is removed ([#468]). The placeholder Welcome page is removed ([#458]). A user denied a page sees a toast that says why, and a user with no permissions sees an explanation instead of an empty dashboard ([#323]). The deny toast now appears exactly once ([#471]), the 403 toast appears on every page ([#480]), and the sidebar no longer flickers on logout ([#325]).

The fifth is **responsive layout**. The dashboard now works on phones. Form inputs no longer trigger the iOS zoom and touch targets reach 44 px ([#338]), the auth pages fill the screen ([#339]), the sidebar behaves as an overlay ([#340]), and data tables switch to cards on narrow screens, with an optional table/cards toggle ([#341]). Pagination ([#342], [#366]), page layout and breadcrumbs ([#343], [#368]), and drawers, dialogs, toasts and dropdowns ([#344]) are sized for small screens. Shared `packages/ui` components show English text when no translations are loaded, as in Storybook ([#363]), and the reason `ToastNotification` has no unit test is documented ([#369]).

The sixth is **end-to-end testing**. The reference app gains a Playwright suite that runs against a seeded test database ([#261]). It covers authentication ([#459]), the landing page ([#460]), the dashboard shell and permission filtering ([#461]), users ([#462]), roles ([#463]), permissions ([#464]), theme and language ([#465]) and the health page ([#466]). It runs with `npm run test:e2e` and in its own CI job, outside `npm run ci`.

The seventh is **toolchain and CI**. Nx moves to 22.7.5 and Angular to 21.2 ([#424]). Integration tests no longer need Docker: they start an embedded Postgres 17 when no test database is configured ([#321]). `npm run ci` now checks formatting first ([#374]), and `npm run ci:verify` runs the same checks through the Nx cache for repeated runs ([#404]). CI uses the Nx Cloud remote cache ([#406]), reads its test-database settings from repository Variables, and runs test, lint and a new type-check job over every project ([#319]). Bugs left over from the monorepo restructure, including stale README paths, are fixed ([#313], [#315]).

The last is **generators, agents and documentation**. A new `ui-component` generator scaffolds shared components, and a lint rule requires every Storybook story to show its source ([#348]). The `drizzle-schema` and `page` generators write kebab-case paths ([#330], [#331]), every generator has unit tests ([#317]), and the generators are documented for people and agents ([#333]). The `/issue-workflow` skill takes an issue from branch to pull request, and `npm install` offers to install the Angular agent skill ([#349]). The agents load their references in parallel and only as needed ([#407], [#410]), run independent advisors in parallel ([#408]), verify with the cached CI ([#405]), and review with a new maintainability lens ([#409]). The domain-model reference gains strategic DDD patterns and corrected examples ([#207], [#380]), and the Bruno error cases use cookie authentication ([#384]).

## [1.0.0-beta.0 – 1.0.0-beta.3] — 2026-04-07

The four pre-releases 1.0.0-beta.0 to 1.0.0-beta.3, cut on 2026-04-06 and 2026-04-07, introduced the fork-distribution model: the starter became a `packages/*` + `apps/reference-app` workspace, gained an app schematic that generates a fork's own app from the reference app, and gained `scope:starter`/`scope:app` boundaries between starter code and fork code. A fork created at an earlier beta has actions to take: read **Fork migration** below before merging. Four follow-ups were recorded but not shipped in these pre-releases: separating `isServerless()` from the app-specific environment constant in `@resetshop/hono-core` ([#258]), a codebase-wide sweep of hardcoded millisecond constants ([#259]), starter presets for the app schematic ([#260]), and end-to-end specs for the reference app ([#261]).

The first area is the **workspace layout**. The single-app repository became an Nx workspace ([#265]), and the code every app shares moved into five packages behind `@resetshop/*` aliases: framework-free helpers in `@resetshop/util` ([#266]), 14 presentational components in `@resetshop/ui` ([#267]), the i18n, theme, navigation and logger providers in `@resetshop/angular-core` ([#268]), the Hono backend infrastructure in `@resetshop/hono-core` ([#269]), and the code generators in `@resetshop/generators` ([#275]). Leftover `@libs/*` aliases from an abandoned `libs/` layout were removed ([#298]).

The second is the **reference app**. Everything app-specific (stores, providers, API modules, database schemas, contracts) now lives in `apps/reference-app`, which replaces the old root-level `src/` and imports the shared code through the package aliases; the Tailwind configuration moved to the workspace root so every project uses the same theme ([#273]). Every project exposes the targets it needs, so CI runs the same checks everywhere ([#286]), and the integration tests are skipped instead of failing when no test database is configured ([#285]). A review pass fixed generator templates that still imported the removed `@libs/*` paths and would have produced code that failed the type-check ([#307]).

The third is **fork distribution**. `npm run generate:app -- --name="My App"` clones the reference app into `apps/<slug>`, which is how a fork creates its own app ([#290]), and `docs/forking.md` documents the whole workflow: who owns which paths, the initial setup, creating an app, and merging upstream ([#291]). Beta.1 enforced the boundary: starter projects are tagged `scope:starter`, fork apps `scope:app`, starter code may not depend on fork code, and lint rejects relative imports across the `apps/` and `packages/` boundary ([#292]). Beta.2 added upstream-only CI guards that keep pull requests away from fork-owned paths and require a changelog entry, together with a pull request template ([#293]). Beta.3 closed the milestone by pointing the CI jobs and the reference app's `serve-static` target at `reference-app`, which still referred to the old `app` project and output folder ([#294]).

The fourth is the **contributor process**. A coding-agent collaboration policy forbids recommending shortcuts on the assumption that the repository has a single maintainer, and `CLAUDE.md` makes it a hard constraint ([#262]).

The **foundations** below were finished in the single-app starter before beta.0, and every fork inherits them. Frontend state moved to NgRx Signal Store, with a store per domain for authentication, users, roles, permissions and the UI ([#33]). New users receive a generated passphrase in a welcome email, and their account carries a `mustChangePassword` flag ([#114]).
